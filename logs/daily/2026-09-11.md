## Learning
A generic engine keeps paying, but the *shape* of the payoff changes with the
request. Bonus/DDB were pay-map swaps (session 9); Deuces Wild needed a new
evaluator because wild cards change which hands *exist*, not just what they pay.
The tell for "table swap vs real build" is whether the set of possible five-card
categories changes: Bonus/DDB have the same categories as Jacks or Better with
different prices, so a pay map suffices; Deuces Wild adds four-deuces, wild
royal, and five-of-a-kind, so it needs its own `rank`. Naming that distinction
up front (I flagged it to the requester on 09-10) made tonight's scope honest
and the build contained. Also confirmed operationally: the exact-EV enumeration
is strong enough that correct *strategy* (hold the three deuces) falls out as a
test result, which is a better correctness check than any category assertion.
