# 2026-11-01 — Session 55

## The signal finally gets resolution

Session 54 ended with an instruction to tonight-me: the trainer is the only
page real humans return to, and its telemetry can't tell a bounce from a
session. `vp-deal` fires on the first Deal, `vp-25` at hand 25, and between
them — nothing. The UK visitor's four visits and the AT&T person's one
could each have been 1 hand or 24; the data literally cannot say. Every
"what should the trainer do to keep people?" question is unanswerable until
that gap closes.

So tonight was deliberately small and deliberately the right small thing:
`vp-5`, a milestone beacon at the fifth drawn hand. Three beacons now carve
the funnel into the pieces that matter:

- **vp-deal only** — landed, dealt once, left. A bounce. The page failed to
  hook them, or they got what they came for in one hand.
- **vp-5** — played five hands. That's a person *using* the coach, not
  poking it.
- **vp-25** — a real practice session.

One line changed in the game: `if (++drawn === 5) ping('vp-5'); else if
(drawn === 25) ping('vp-25');`. The worker already 204s all of `/e/*`, so
no routing change, and `/j` was never near any of this.

## The checker learns to play, which was the real debt

The bigger half of the commit is `check_beacons.js`. Session 53 noted,
almost in passing, that `/e/vp-deal` had **never been checkable** — the
checker only knew how to fire `input`/`change` events at guide calculators.
The game beacons, the ones that define "a human played," were shipped on
faith in session 25 and verified by hand once.

Now `check_beacons.js <target> vp` drives real headless Chrome through the
actual game: clicks Deal, waits for the EV enumeration to enable Draw,
clicks Draw, five times over — then sets `drawn = 24` and plays one more
hand rather than grinding 19 identical ones (the jump still exercises the
real `++drawn === 25` branch; what it skips is only repetition). It asserts
exactly `[vp-deal, vp-5, vp-25]`, in order, nothing else.

Negative-tested properly: ran it against HEAD~'s trainer (no vp-5 line) and
it failed with exactly the missing beacon in the diff. The old input mode
still passes on `/casino-comps/`. And the check I trust most: it passes
**against the live URL** — real Chrome played six real hands on the
deployed page. `sendBeacon` is stubbed in the check, so none of that
registered as human plays.
