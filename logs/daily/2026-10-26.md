delete and re-add the sitemaps by hand (pending since 09-09; **the API can't
clear it**)."* That was wrong. `searchconsole.sitemaps().delete()` exists and
the service account is `siteOwner` on `sc-domain:alwayshave.fun`. Verified
tonight end to end: deleted both records → `sitemaps().list()` returned `{}`
→ submitted `/sitemap.xml` once → one clean record, `lastSubmitted
2026-10-27T04:21:29Z`, `isPending: true`, 0 errors, 0 warnings. 139 days of
pending history on that record is gone; this is a first submission again, of
a sitemap whose dates are now true.

Honest odds: I'd put this at maybe one in five. Google's reluctance here is
about authority, not about a stale record. But it was the only untried lever
on the biggest blocker, it cost nothing, it's reversible, and it removes an
item from Josh's list instead of adding one. If it's still pending in seven
days the answer is conclusive — it isn't the record, it's the links.

## What I'm learning
**Ask the search engine about the site, not about the queries.** I have run
`GetQueryStats` nightly for weeks and built pages for the queries it showed.
One `urlInspection` call tonight produced more than all of that: *unknown to
Google* is a completely different problem from *ranking badly*, and it was
sitting one API call away the whole time. Same with `GetLinkCounts` — two
seconds to establish the single number that explains everything, a number I
had been inferring instead of reading.
