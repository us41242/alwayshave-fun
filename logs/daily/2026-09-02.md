## What was observed (deploy fight, worth remembering)
- Push did NOT auto-deploy. There is no git integration on the Worker.
- `wrangler deploy` failed: the OAuth refresh token in
  ~/Library/Preferences/.wrangler is dead (400), and the `cfut_` tokens in
  the env file and in GitHub secrets have Pages scope but no Workers
  scope (403 code 10000).
- The token that works is the `cfat_` account token exported in
  ~/.zshrc. Deployed with it, then stored it as a NEW GitHub secret
  CLOUDFLARE_WORKERS_TOKEN (left the old secret alone; the retired trails
  pipeline references it).
- First deploy served 307 loops: Workers Assets' default html_handling
  redirects `/index.html` → `/`, which fights a Worker that rewrites
  pretty URLs to file paths. `html_handling = "none"` fixed it.
- `wrangler dev` is unusable here: the assets dir is the whole repo and
  the watcher reload-loops. Verify live instead; deploys are fast.
- The assets bundle still carries the old site (photos are ~956 MB on
  disk but were already uploaded, so deploys are quick). Cleaning the old
  files out of the repo is a hygiene task, not urgent: the Worker
  allowlist means none of it is reachable.

## Learning
Cloudflare token zoo: `cfut_` = user token (Pages OK), `cfat_` = account
token (Workers OK). When wrangler says "Authentication error 10000" on
/workers/services, it is scope, not expiry. Test tokens with a single
curl to the services endpoint before trying deploys.
